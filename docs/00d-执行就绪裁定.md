## 二、对评审规格的 3 处修改（不完全照抄）

| # | 评审原案 | 修改 | 理由 |
|---|---------|------|------|
| 1 | `tokens[]` 放 `knowledge_doc_versions` | 移到 `knowledge_docs`（当前版本） | 检索语义 = 搜"当前版本"；历史版本保持不可变（只做回滚来源）。回滚 = 用旧版本内容创建新版本 + 重算当前 tokens，历史不被污染 |
| 2 | 事件 enum 5 类 | 扩为 6 类：+`submit_api_failed` | 客户端网络失败（请求根本没到服务端）是"提交成功率"分母的关键盲区，必须能回填上报；否则提交成功率口径不成立 |
| 3 | 状态机引用 retry_count 但未给字段 | `forms` 增加 `retry_count tinyint default 0` | 状态机 failed→processing 的重试上限需要落表，否则状态机不可实现 |

- **P6 内部顺序**：文档域 CRUD（必做）→ Spark 同构 → RAG → 报表预测。
- **P1 交付**：`docs/08-需求覆盖矩阵.md` 骨架先行（采纳 00c T1 意见）。
- **交付物清单**：补齐 `artifacts/` 证据树（采纳 00c T1 意见）。
- **埋点隔离**：埋点写库不得与业务副作用同 try 块（失败只记日志）——写入 §4.10。

## 四、D 题裁定（4 项技术决策，面试口径已备）

| 决策 | 裁定 | 理由（技术面可直接讲） |
|------|------|----------------------|
| JWT 算法 | **HS256** | 单体服务、无多服务验签/公开 JWKS 需求，对称密钥足够且少一半配置；RS256 非对称优势在此不成立。候选人在实习中做过 RS256——写入文档作为"生产路径"参照，体现"两边都懂、按场景选" |
| Mongo 镜像 | **P0 拉取 `mongo:7`** | 题目点名知识文档存储；00c T4 已实测 Docker Hub 非沙箱可达、本机无 Mongo 镜像。拉取失败按 blocker 流程记录，不做静默降级 |
| Spark 运行环境 | **conda 建 `spark311`（Python 3.11）**，复用 `/home/lx/spark` 发行包 | 00c 实测：Py3.13 最小作业可跑但非官方稳态组合；演示要的是确定性，不赌兼容性。代价 ≈ 一条 conda 命令 |
| 地图底图 | **OpenFreeMap（无 Key）→ OSM raster 备选 → 无底图降级** | MapLibre 库无 Key ≠ 底图服务无条款/配额风险；演示不能单点依赖外部 tile 服务，README 写明三级切换 |
