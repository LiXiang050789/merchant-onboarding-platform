# 提交成功率统计设计

> P3 产物。代码证据见 `backend/app/stats.py`、`backend/tests/test_success_rate.py`，测试证据见 `artifacts/test/p3.xml`。

## 事件模型

成功率统计只读取 `submission_events`，不从请求日志反推。事件类型为：

- `submit_attempt`
- `submit_api_success`
- `submit_api_failed`
- `db_insert_success`
- `validation_failed`
- `business_published`

`form_audit_events` 只负责审计，不混入成功率口径。

## 三种口径

| 口径 | 分母 | 分子 | 说明 |
|---|---|---|---|
| 提交成功率 | 窗口内去重后的 `submit_attempt` | 同一幂等键出现 `submit_api_success` | 客户端/网络视角，重试成功按成功算。 |
| 落库成功率 | 窗口内去重后的 `submit_attempt` | 同一幂等键出现 `db_insert_success` | 服务端视角，校验失败不会进分子。 |
| 端到端成功率 | 窗口内去重后的 `submit_attempt` | 同一幂等键出现 `business_published` | 业务视角，关注最终态。 |

重复提交用 `(tenant_id, idempotency_key)` 去重；同一窗口内多次 attempt 只取首次 attempt 作为分母样本。
窗口按 `received_at` 归集。分母只统计 `[from,to]` 内收到的 `submit_attempt`；同一幂等键的成功、落库、发布事件允许在 `to` 后 10 分钟内迟到，超过容忍窗口则进入后续统计窗口，不回写历史窗口。

## 缓存

统计接口使用 Redis key：

```text
success_rate:v1:{tenant}:{from}..{to}:all
```

TTL 为 30 秒。Redis 失败时只回退为实时 SQL 计算，不影响接口结果。

## API

`GET /api/v1/stats/success-rate?from=...&to=...` 返回：

- `submit_success_rate`
- `db_success_rate`
- `end_to_end_success_rate`
- `deduped_attempts`

不传 `from/to` 时默认近 24 小时；接口强制使用当前登录用户的 `tenant_id`，跨租户事件不会参与统计。
