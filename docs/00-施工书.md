## 0. 一句话总览

把题目 7 块要求串成**一条 B 端业务主线**，不做技术展览：

> 企业提交入驻表单 → 权限与校验保障数据准确 → 按地理坐标聚合成作业批次 → 批处理管线处理四类表单 → 报表统计 + 成功率监控

**定位声明**（对齐题目前言"B 端看重效率而非体验"）：这是一个**数据处理平台**，UI 克制，重点在数据准确性、查询效率、可观测性。

## 2. 系统架构

```
┌──────────────────────────────────────────────────────────────────┐
│  前端  Next.js 15（锁定 15.x，App Router, TS）· MVVM 分层           │
│   View 组件 ← ViewModel(zustand + hooks) ← Model(API/类型/缓存)     │
│   地图: MapLibre GL (WebGL, BSD-3, 无 Key) · 底图三级降级（见 §7）   │
│   数据: TanStack Query + ETag 协商缓存 + WebSocket 增量             │
│   页面: /map /forms /batches /stats /docs                         │
└───────────────────────────┬──────────────────────────────────────┘
                            │ REST + WebSocket(单频道) + 轮询降级
┌───────────────────────────┴──────────────────────────────────────┐
│  后端  FastAPI (async, driver=asyncmy)                            │
│  ├─ 权限域  RBAC + tenant 隔离 + 审计事件（一级设计）                 │
│  ├─ 表单域  统一主表 + 4 类 schema + 状态机 + 多维过滤器 + 埋点 + 异常 │
│  ├─ 聚合域  度网格分桶(渲染) + 网格候选+距离排序(批次) + 基准对比      │
│  ├─ 统计域  6 类事件 → 成功率 3 口径 → API                          │
│  ├─ 批处理  Python 管线(主) + PySpark(同构验证) + DLQ/checkpoint    │
│  └─ 文档域  知识文档 CRUD/版本/软删/jieba 检索 + RAG(限时加分)        │
└──────┬──────────────────┬──────────────────┬─────────────────────┘
    MySQL 8            MongoDB 7            Redis(本机)
 表单/事件/批次/审计   知识文档+版本+检索   缓存/计数/PubSub
```

**技术选型与理由（why / why-not，面试直接用）：**

| 选择 | 为什么 | 为什么不选替代 |
|------|--------|---------------|
| Next.js **15**（pin 15.x，不装 latest） | 题目点名 nextjs；SSR 首屏 + 路由级代码分割；版本冻结防未知 breaking（当前 npm latest 已是 16.x） | 16 未验证收益；纯 SPA 首屏白屏久 |
| **Node.js 说明** | Node 仅作为 Next.js 服务端运行时（SSR/Route Handler），不单独写 Node 后端 | 题目点名 nodejs 已由 Next 运行时覆盖；双后端 = 双倍讲解成本 |
| MapLibre GL | 开源（BSD-3）无 Key、WebGL 渲染、GeoJSON 原生 | 高德/百度要 Key 不便公开；Leaflet 是 DOM 渲染，万级点会卡 |
| **度网格分桶**（渲染聚合主路径） | 10 秒能讲清、零额外依赖、按 zoom 选精度即可覆盖 10w | H3：层级汇总优雅但依赖+解释成本；PostGIS：易变成"数据库扩展配置题"；supercluster：不适合带过滤条件的服务端聚合；Tippecanoe：离线瓦片，不适合动态表单 |
| **网格候选+距离排序+容量约束**（批次聚合） | 可解释性优先：贪心最近合并，Haversine 校验距离；容量约束天然融入 | cKDTree：O(n log n) 更优但收益在 10w 规模不显著（基准为证），保留为基准对照；容量约束聚类严格最优是 NP-hard，工程贪心足够且可审计 |
| FastAPI | async + 原生 WebSocket + Pydantic 校验 + 自动 OpenAPI | **Flask（题目并列点名）**：无原生 async/WS，需 gevent/扩展拼装，且与 SQLAlchemy async 生态割裂；本设计有 WS 与高并发查询诉求，故选 FastAPI 并在文档显式论证 |
| 统一 forms 主表 + form_type + 物化列 + JSON payload | 单表支撑四类表单的聚合/过滤/统计，避开 UNION；物化列可建真实索引，EXPLAIN 出证据 | 四张独立表：聚合与统计要 UNION，叙事碎 |
| MySQL 8 + **asyncmy** 驱动 | 题目点名 sql/MySQL；EXPLAIN + 复合索引优化叙事；asyncmy 是 SQLAlchemy async 的成熟 MySQL 驱动 | aiomysql 亦可，选 asyncmy（纯 Python、维护活跃） |
| MongoDB 7 | 知识文档天然文档模型：动态字段+版本+软删 | MySQL JSON 能做但版本/检索要手写 |
| Redis（本机已启动） | 缓存/成功率计数/PubSub | — |
| **jieba 预分词 + tokens[] 数组 + multikey 索引** | Mongo text index 按空格/标点分词，中文长句近乎不可用（00c T4 核实）；预分词后数组字段可精确匹配+可加权 | Atlas Search（本地不可用）；ES（一周工期过重） |
| Python 管线（批处理主） | 10w 级单机最快、依赖最少、演示稳定 | Spark 在此规模启动开销 > 收益（诚实呈现） |
| PySpark（同构验证，py3.11 专用环境） | 展示分布式路径（JD 点名）；同构测试证明语义一致 | 不做真跑=空谈；只做"可运行 demo"不做双主路径 |
| **不引入 C++** | 热点在 IO 与渲染；numpy 向量化后 C++ 核收益 <5%，可维护性优先 | JD 点名，但**主动评估后不引入 + 文档论证**比硬塞更专业 |
| **不实现 IndexedDB** | 题目只要求缓存与网络请求，非离线优先；三层缓存已闭环 | 降级为跨端文档里的离线策略说明 |
| JWT：**HS256** | 单体服务，对称密钥足够；少一半配置（无密钥对管理） | RS256：非对称优势（多服务验签/公开 JWKS）在此不成立；候选人有 RS256 实习经验，文档记为"生产路径"参照 |

## 3. 关键设计决策（面试答辩核心，精确规格见 §4）

### 3.1 权限与数据准确性（一级设计）
角色：企业账号（仅见自己 tenant）/ 区域运营（按 geo 区域=city_code 审核）/ 管理员。
隔离：所有查询强制携带 tenant 作用域（**repository 层统一注入**，不靠每个接口自觉）；跨租户访问一律 404（不泄露存在性）。
准确性：Pydantic 类型校验 + 经纬度范围校验（中国境内边界）+ 必填/枚举校验 + 状态机流转合法性（非法 409）。
审计：`form_audit_events` 记录 actor、from→to、payload 摘要，不可变更。

### 3.2 两级聚合，别混淆（核心概念区分）
- **渲染聚合** = 度网格分桶：解决"10w 点怎么画不卡"——查询优化问题。zoom 决定格大小，客户端永远只收几百簇。
- **业务批次** = 网格候选 + 距离排序 + 容量约束：解决"哪些申请打包给同一片区运营"——业务分组问题，有容量上限、有状态、被管线消费。
- 为什么不能混用：渲染簇随视野/zoom 变化且无容量约束；业务批次必须稳定、可审计、可指派。
- "最近"语义（v3 收紧）：网格只做候选缩小；批内排序与合批判定用距离，"近"有确切定义（近似公式排序 + Haversine 校验 + 半径上限），见 §4.4。

### 3.3 数据不下发原则
`GET /api/v1/clusters?bbox=&zoom=&filters=` → 当前视野 + zoom 的簇（目标 <500 feature / <200KB）。基准证据：全量下发 vs 聚合下发的 payload 与 P95 对比。

### 3.4 成功率三种口径（追问焦点，精确 SQL 见 §4.5）
| 口径 | 公式 | 视角 |
|------|------|------|
| 提交成功率 | `submit_api_success / submit_attempt` | 客户端（含网络失败） |
| 落库成功率 | `db_insert_success / submit_attempt` | 服务端（含校验拒绝） |
| 端到端成功率 | `business_published / 去重后 submit_attempt` | 业务（跨批处理） |

工程点：客户端幂等键（UUID，随表单实例持久化）→ 服务端唯一索引去重；重试成功按**最终态**统计；乱序事件按时间窗归集（细节 §4.5）。

### 3.5 缓存三层（精确协议见 §4.7）
HTTP ETag/304（浏览器）→ Redis（簇结果/统计窗口）→ TanStack Query（staleTime/invalidate）。写操作 → 后端删缓存 + WS 推送 → 前端 invalidate。

### 3.6 批处理工程要素
幂等（批次 ID + 记录级幂等键）｜断点续跑（checkpoint）｜失败隔离（DLQ + 指数退避）｜可观测（每阶段埋点）。

### 3.7 表单状态机（四类共用骨架，完整表见 §4.3）
```
draft → submitted → validating → validated → batched → processing → published
                        ↘ rejected（校验失败，终态）
                                              ↘ failed（可重试，retry_count<3）
```
非法流转 409 且有测试覆盖。

### 3.8 知识文档设计（R4）
Create 建 v1；Update 乐观锁（`If-Match` + version_no）生成新版本；Delete 软删（默认不可见）；回滚 = 基于历史版本创建新版本（不覆盖历史）；检索 = jieba 预分词 tokens 数组 + multikey 索引（搜"当前版本"）。

### 4.2 API 契约

统一响应信封：成功 = 业务数据；错误 = `{code, message, detail?, trace_id}`。错误码：400 校验失败｜401 未登录｜403 越权｜404 不存在或跨租户隐藏｜409 幂等冲突/非法状态/版本冲突｜422 业务字段错误｜500 未预期。

| 方法 | 路径 | 请求/响应要点 |
|---|---|---|
| POST | `/api/v1/auth/login` | email/password → `access_token, refresh_token, expires_in` |
| POST | `/api/v1/auth/refresh` | refresh_token → 新 access_token |
| GET | `/api/v1/forms` | filters(city/status/form_type/industry/from/to) + `page,size`（深分页问题文档写 keyset 建议）→ `items,total,page,size` |
| POST | `/api/v1/forms` | `Idempotency-Key` header + body；重复键返回原 form（200） |
| GET | `/api/v1/forms/{id}` | tenant scope |
| PATCH | `/api/v1/forms/{id}/status` | `target_status`；非法流转 409 |
| GET | `/api/v1/clusters` | `bbox,zoom,form_type,status,city,from,to` → GeoJSON FeatureCollection；feature.properties = `{cluster_id,count,centroid:[lng,lat]}` |
| POST | `/api/v1/batches/build` | filters + `capacity`,`radius_m` → batch summary |
| GET | `/api/v1/batches` | 分页 |
| POST | `/api/v1/batches/{id}/run` | 幂等触发（重复触发返回同一 run） |
| GET | `/api/v1/stats/success-rate` | `window`(默认24h) + filters → 三口径数值 + 分母样本量 |
| POST/GET/PATCH/DELETE | `/api/v1/docs` | CRUD；PATCH 带 `If-Match`（version）；DELETE 为软删 |
| POST | `/api/v1/docs/{id}/rollback` | `{version_no}` → 新版本 |
| GET | `/api/v1/ws?token=` | WS 握手（浏览器 WS 不能带 header）；事件 `{type,payload,sent_at,seq}`；type ∈ `form.status_changed`,`batch.status_changed`,`doc.updated` |
| GET | `/api/v1/events?since={seq}` | **轮询降级端点**（WS 不可用时前端切换） |

鉴权：JWT **HS256**（`.env` 密钥），access 30min / refresh 7d；WS 首连用 `?token=`，服务端校验后绑定 tenant；WS handler 只鉴权一次 + 订阅 PubSub，DB 操作用短 session（不长期占用连接）。

### 4.3 状态机（完整流转表）

| from | to | 触发者 | 条件 | 拒绝语义 |
|---|---|---|---|---|
| draft | submitted | merchant | 必填字段完整 | 422 |
| submitted | validating | system | 入队校验 | 409 非 submitted |
| validating | validated | system | schema/坐标/权限通过 | 409 |
| validating | rejected | system/operator | 校验失败 | 记录原因，终态 |
| validated | batched | system | 被批次选中 | 409 |
| batched | processing | worker | 批处理启动 | 409 |
| processing | published | worker | 管线完成 | 409 |
| processing | failed | worker | 可重试异常 | 写 DLQ，retry_count+1 |
| failed | processing | worker/operator | `retry_count < 3` | 超限保持 failed |

### 4.4 聚合参数

| 参数 | 冻结值 |
|---|---|
| zoom→grid size | z≤8: 0.2°；9–10: 0.1°；11–12: 0.05°；13–14: 0.02°；≥15: 0.01° |
| bbox | `[west,south,east,north]`，校验 west<east、south<north |
| 批次容量 | 50 条/批 |
| 最大合批半径 | 3000m（同城市内生效） |
| 距离公式 | 候选排序用等距圆柱近似：`x=(lng2-lng1)*cos(avgLat)*111320`，`y=(lat2-lat1)*110540`（米）；合批终判用 Haversine 校验 |
| 跨城市 | 先按 `city_code` 分区，禁止跨城市合批 |
| 查询范围 | 所有聚合查询强制 tenant + 可选 city 过滤（走 §4.1 复合索引） |

### 4.5 成功率 SQL 语义

| 口径 | 分母 | 分子 | 去重规则 |
|---|---|---|---|
| 提交成功率 | `submit_attempt` | `submit_api_success` | 按 `(tenant_id,idempotency_key)` 每窗口取首次 attempt |
| 落库成功率 | `submit_attempt` | `db_insert_success` | 同上 |
| 端到端成功率 | 去重后 `submit_attempt` | 最终状态 `published`（`business_published` 事件） | 以 `idempotency_key` 归集最终态 |

时间窗：按 `received_at` 入窗；允许 10 分钟迟到；默认近 24h，支持 `from/to`；离线回填事件（`submit_api_failed` 晚到）计入接收窗口并在文档注明。

### 4.6 合成数据规格（写死在生成器常量里）

种子 `20260918`；100000 条 forms。城市权重：上海 30%、北京 25%、深圳 20%、杭州 15%、成都 10%；每城 5 个商圈中心，高斯扰动 σ=0.02°。异常注入：坐标越界 0.5%、缺必填 1%、重复幂等键 1%、非法状态样本 0.2%。状态分布：published 85%、processing/batched 8%、rejected 3%、failed 2%、draft 2%。事件历史：每表单 1–3 次 attempt，attempt 网络失败率 3%（客户端事件）、落库校验失败 1%；P3 测试以"由事件表重算的期望值"断言统计 SQL（不硬编码数字），并单独断言注入量（如越界坐标 = 500 条）。界面与文档标注"合成数据仅用于演示"。

### 4.7 缓存与失效协议

| 事件 | 后端动作 | 前端动作 |
|---|---|---|
| form_created / status_changed | 删 `clusters:*`、相关 stats key；发布 WS | invalidate `forms`,`clusters`,`stats` |
| batch_created / batch_updated | 删 batch list key；发布 WS | invalidate `batches`,`clusters` |
| doc_updated / doc_deleted | 删 docs key；发布 WS | invalidate `docs` |

ETag：弱 ETag `W/"v1:{resource}:{filter_hash}:{max_updated_at_epoch}:{row_count}"`；配合 `Cache-Control: no-cache`（每次协商，304 省 body）。
TanStack Query：列表 `staleTime=30s, gcTime=5min`；统计 `staleTime=10s`；聚合 `staleTime=15s`。

### 4.8 前端路由与 MVVM 边界

| 路由 | View（只渲染） | ViewModel（状态与交互） | Model（API/类型/queryKey） |
|---|---|---|---|
| `/map` | 地图 + 筛选 UI | bbox/zoom/filter 状态 | `clusterApi`, query keys |
| `/forms` | 表格/详情抽屉 | 分页/筛选/状态动作 | `formApi` |
| `/batches` | 批次列表/运行按钮 | 批次状态 + WS 消息 | `batchApi` |
| `/stats` | 成功率卡片/趋势 | window/filter | `statsApi` |
| `/docs` | 文档列表/编辑器 | 当前版本/etag | `docApi` |

目录（MVVM 在代码结构里"看得见"）：`frontend/src/features/{map,forms,batches,stats,docs}/{view,view-model,model}` + `shared/`。

### 4.9 基准测量

命令：`python scripts/benchmark_aggregation.py --n 100000 --seed 20260918 --out artifacts/bench/aggregation.json`

三类工作负载（对同一组固定查询集统计 P50/P95）：
1. **渲染聚合**：N 个随机 bbox/zoom 查询：全扫描（无分桶，numpy 向量化）vs 网格分桶 vs cKDTree 预建；
2. **批次构建**：网格候选贪心 vs cKDTree 候选贪心（容量 50、半径 3000m），正确性对拍（与暴力排序基线一致）；
3. **payload 对比**：全量下发 vs 聚合下发的字节数与 feature 数。

JSON 字段：`workload,algorithm,n,p50_ms,p95_ms,total_ms,payload_bytes,features_count,peak_memory_mb,correctness_passed`。
另产出 `artifacts/bench/explain.txt`：forms 过滤查询 EXPLAIN（索引命中）证据。
前端（Playwright）：`first_contentful_paint_ms,map_features,filter_refresh_ms,screenshot_path` → `artifacts/frontend/perf.json`。

### 4.10 埋点

服务端中间件：`trace_id,tenant_id,user_id,method,path,status_code,duration_ms,error_code,created_at`（trace_id 贯穿响应信封）。
前端批量上报：`page_view,filter_change,submit_attempt,submit_api_success,submit_api_failed`（失败队列重试，随 `client_trace_id` 去重）。
**隔离铁律：埋点写库失败只记本地日志，绝不影响业务请求结果**（不得与业务副作用同 try 块）。

### 4.11 测试环境

独立测试库 `merchant_test` / `merchant_docs_test`（**禁止复用开发库**）；pytest session fixture 建连接，function fixture 清表/清集合。必测用例：越权访问、重复提交（幂等）、非法状态流转、非法坐标、过滤器组合、并发版本冲突（乐观锁）、软删不可见、批处理重跑幂等、checkpoint 续跑、DLQ 重试、三口径统计与事件重算一致。
