# 跨端适配方案

## Web 桌面端

桌面端是主交付形态，使用 Next.js 15：

- 地图页展示聚合 marker、筛选器和实时刷新。
- 表单、批次、统计、文档页采用表格和紧凑面板，优先信息密度。
- TanStack Query 负责缓存、重试、失效；后端 ETag/304 降低重复 payload。

## 移动端 Web

移动端不强行复刻完整地图操作：

- `/map` 保留筛选器，但默认展示聚合列表和数量摘要。
- 地图容器保持固定高度，低性能设备可降级为 GeoJSON 列表。
- 表格改为窄屏卡片，保留状态、城市、类型、时间和主要操作。
- 批次运行等高风险操作保留二次确认。

## 小程序 / uni-app 路径

不在本作业内实现小程序，但接口设计可复用：

- 登录后保存 access token，刷新 token 走 `/api/v1/auth/refresh`。
- 表单列表、统计、批次、文档 CRUD 均是 REST API，可直接封装为 uni-app service。
- 地图能力使用平台地图组件；若 marker 过多，仍消费 `/api/v1/clusters`。
- WebSocket 不稳定时使用 `/api/v1/events?since=` 轮询降级。

## 大屏端

大屏只读，不做审核操作：

- 成功率三口径卡片。
- 城市/行业/表单类型聚合趋势。
- 批次状态总览。
- 通过 WebSocket 或轮询接收增量事件。

## PWA 离线策略

本项目未实现完整 PWA，但设计上可扩展：

- 静态资源由 Next.js 缓存。
- 表单草稿可进入 IndexedDB，但本次按评审裁定不做，避免一周内分散主线。
- 离线创建必须带客户端幂等键；恢复联网后重放，服务端按 `(tenant_id,idempotency_key)` 去重。

## 底图降级

三级策略：

1. OpenFreeMap/MapLibre 矢量底图。
2. OSM raster 底图。
3. 无底图，仅展示 GeoJSON 聚合点和右侧列表。

答辩口径：B 端核心是数据准确与效率，底图只是辅助定位；无底图时业务流程仍可完成。
